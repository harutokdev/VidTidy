# ADR-001〜008: Architecture Baseline v1

| ADR | 決定 | 理由 |
|---|---|---|
| ADR-001 | .NET 10 LTS / C# / WPF / MVVMを採用する。 | 指定技術スタックを遵守し、Windowsの長時間ローカル管理UIに適合させる。 |
| ADR-002 | SQLite + Microsoft.Data.Sqlite + explicit SQLを採用する。 | DBスキーマ、短いtransaction、migration、indexを明示管理し、ORMを導入しない。 |
| ADR-003 | C# Core/InfrastructureをDB唯一のwriterとし、Python WorkerはDB非所有とする。 | durable stateとmigration責任を一箇所へ固定し、Worker障害がDB整合性を損なわないようにする。 |
| ADR-004 | 将来Worker IPCはversioned gRPC/Protobuf、127.0.0.1限定、per-launch tokenとする。 | LAN公開を避け、Health/progress/result/cancelを型付きで進化させる。 |
| ADR-005 | MediaFileとMediaContentを分離する。 | path/locationとcontent identityを混同せず、将来Full SHA-256により複数locationを同一contentへ束ねられるようにする。 |
| ADR-006 | SQLiteはWAL、foreign_keys=ON、busy_timeout=5000、synchronous=FULLとし、idle後にTRUNCATE checkpointする。 | 原本から独立したDBのdurabilityを優先し、WALの無制限肥大化を避ける。 |
| ADR-007 | Portable判定はAppRoot直下の`portable.flag`とする。 | 明示的・決定的で、DB/cache/runtime/models/tempをAppRoot相対に隔離できる。 |
| ADR-008 | QuickFingerprintはsample hashの候補抽出専用で、完全重複確定はFull SHA-256に限定する。 | 数TB初回走査のコストを抑えつつ、heuristicをexact proofとして誤用しない。 |

## 運用上の補足

FFmpeg/ffprobeはRuntimeRoot配下を第一候補とし、無い場合は`FFMPEG_NOT_FOUND`をJob errorとして保存する。実行時ダウンロードは行わない。Rootが到達不能なときは`Offline`へ記録し、その配下のMediaFileをMissingへ一括確定しない。absence判定はOnline RootのScanが`Completed`となった後に限る。
